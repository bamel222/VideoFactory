Guide de déploiement sur OVHCloud

Mettre en ligne l'application de A à Z, du premier clic dans l'espace client OVH jusqu'à la génération de la première vidéo — avec toutes les informations qui manquaient auparavant (clé SSH, pare-feu, utilisateur S3, dépannage).

Vue d'ensemble : l'application est composée de 6 services Docker (nginx, frontend, backend, worker, postgres, redis). Les vidéos générées sont stockées dans un bucket Object Storage OVH (S3-compatible). Dans un premier temps, le pipeline produit une vidéo « placeholder » (images unies + sons de test) — le contenu réel viendra avec les vrais providers IA.

01Prérequis

  • Un compte OVHcloud actif (espace client).
  • Une clé SSH publique (pour se connecter au serveur). Si vous n'en avez pas : générez une paire sur votre PC.
  • Les identifiants du bucket Object Storage (access key + secret key), ou la possibilité d'en créer.
  • Un token GitHub pour cloner le repo privé (voir étape 06).

Générer une clé SSH (si nécessaire)

Sur votre PC (PowerShell ou Git Bash) :

ssh-keygen -t ed25519 -C "votre-email@exemple.com"

Cela crée deux fichiers : la clé privée (à garder secrète, ex. ~/.ssh/id_ed25519) et la clé publique (~/.ssh/id_ed25519.pub). La clé publique est celle qu'on colle dans OVH.

02Créer l'instance Public Cloud

  1. Espace client OVH → Public Cloud → Instances → Créer une instance.
  2. Renseignez :
    • Région : idéalement la même que votre bucket Object Storage (ex. Paris).
    • Image : Ubuntu 22.04 LTS (ou 24.04).
    • Modèle (flavor) : b2-7 (2 vCPU, 7 Go RAM) minimum — l'encodage vidéo 1080p est gourmand.
    • Clé SSH : collez votre clé publique (l'étape qui affiche un champ « Clé SSH publique »).
  3. Créez l'instance, puis notez l'adresse IP publique qui s'affiche.
Astuce coût : le Public Cloud est facturé à l'heure. Éteignez l'instance quand vous ne l'utilisez pas (vous ne payez alors que le stockage du disque).

03Ouvrir le pare-feu (ports 80 et 22)

C'est une étape qu'on oublie souvent, et c'est elle qui fait que « la page ne se charge pas » depuis l'extérieur.

  1. Espace client OVH → Public Cloud → votre instance → onglet « Security groups » (ou « Groupe de sécurité »).
  2. Assurez-vous que ces ports sont ouverts en entrée :
    • Port 22 (SSH) — pour se connecter.
    • Port 80 (HTTP) — pour accéder à l'application.
  3. Si une règle manque, ajoutez-la (type TCP, port, source « partout » ou votre IP).
Plus tard (HTTPS) : quand vous ajouterez un nom de domaine, il faudra aussi ouvrir le port 443.

04Se connecter en SSH

Depuis votre PC, avec votre clé privée :

# Exemple avec la clé privée .pem téléchargée (adaptez le chemin et l'IP) ssh -i C:/Users/ToshR/Downloads/ovh_cle_ssh_privee.pem ubuntu@57.130.39.132

À la première connexion, répondez yes à la question sur l'empreinte (fingerprint).

Erreur fréquente « Permission denied (publickey) » : cela signifie que la clé publique n'a pas été associée à l'instance, ou que vous pointez vers la mauvaise clé privée. Vérifiez que la clé publique a bien été ajoutée à la création de l'instance.

05Installer Docker

Une fois connecté au serveur :

sudo apt-get update sudo apt-get install -y docker.io docker-compose-plugin sudo usermod -aG docker $USER # se déconnecter puis se reconnecter pour activer le groupe docker exit

Reconnectez-vous, puis vérifiez :

docker --version docker compose version

06Récupérer le code

git clone https://github.com/bamel222/VideoFactory.git cd VideoFactory
Le repo est privé : git vous demandera vos identifiants. Utilisez votre nom d'utilisateur GitHub + un token d'accès personnel (pas votre mot de passe — GitHub ne l'accepte plus).

Créer un token GitHub (si besoin)

  1. GitHub → votre avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
  2. Generate new token → sélectionnez le repo bamel222/VideoFactory → permission Contents : Read-only (suffit pour cloner/puller).
  3. Copiez le token, puis utilisez-le comme « mot de passe » lors du clone.

Pour éviter de ressaisir le token à chaque git pull, enregistrez-le une fois :

git config --global credential.helper store

07Configurer les secrets (.env)

cd ~/VideoFactory/infra cp .env.production.example .env nano .env

Générez les deux secrets obligatoires (à coller dans le fichier) :

openssl rand -base64 32 # → collez dans ENCRYPTION_KEY openssl rand -base64 32 # → collez dans JWT_SECRET

Renseignez aussi :

VariableValeur
POSTGRES_PASSWORDun mot de passe fort (base de données)
ENCRYPTION_KEYle résultat d'openssl rand -base64 32
JWT_SECRETun autre openssl rand -base64 32
APP_BASE_URLhttp://57.130.39.132 (votre IP)
Critique : sans ENCRYPTION_KEY et JWT_SECRET forts, le backend refuse de démarrer en production (garde-fou de sécurité intégré).

08Lancer le déploiement

cd ~/VideoFactory docker compose -f infra/docker-compose.deploy.yml --env-file infra/.env up -d --build

Le premier build prend 10 à 20 minutes (installation des dépendances + build Next.js). Attendez le retour au prompt.

Vérifiez que les 6 conteneurs sont en Up :

docker compose -f infra/docker-compose.deploy.yml ps

Puis testez le backend (doit renvoyer du JSON, pas du HTML) :

curl -s -X POST http://localhost/api/v1/auth/login \ -H "Content-Type: application/json" \ -d '{"email":"owner@vf.ai","password":"password123"}'

09Configurer le bucket OVH (Object Storage)

9.1 — Créer le bucket

  1. Espace client OVH → Object Storage → Créer un conteneur/bucket.
  2. Choisissez la solution S3 API, la région Paris, et un nom tout en minuscules, sans underscore (ex. ovh-stockage-videos).
Règle de nommage S3 : les noms de bucket n'acceptent que les lettres minuscules, chiffres et tirets. Pas de majuscules, pas de _, pas d'espaces. Un nom invalide provoque des erreurs de connexion.

9.2 — Créer l'utilisateur S3 (avec les bons droits)

  1. Espace client OVH → Object Storage → onglet « S3 Users » → Créer un utilisateur.
  2. Notez immédiatement l'access key et la secret key (la secret key ne s'affiche qu'une fois).
  3. Allez dans « My containers » → votre bucket → menu « … » → « Add user » → sélectionnez votre utilisateur → rôle « ObjectStore operator » (ou Administrator).
Point crucial : le rôle doit inclure la permission de suppression (s3:DeleteObject). Sans elle, le nettoyage automatique des fichiers intermédiaires échouera silencieusement et votre bucket se remplira de fichiers inutiles.

9.3 — Les codes de région OVH

RégionCodeEndpoint S3
Pariseu-west-parhttps://s3.eu-west-par.io.cloud.ovh.net
Gravelinesgrahttps://s3.gra.io.cloud.ovh.net

Attention à la confusion : eu-west-par-b (vu sur la page de l'instance) est la zone de disponibilité de l'instance de calcul, PAS le code Object Storage. Pour le stockage, c'est eu-west-par (sans le -b).

10Brancher le stockage dans l'app

  1. Ouvrez l'app http://57.130.39.132 → connectez-vous en owner.
  2. Stockage → remplissez :
    • Nom : OVH Bucket
    • Type : s3
    • Priorité : 1
    • Région : eu-west-par
    • Config (JSON) :
{
  "endpoint_url": "https://s3.eu-west-par.io.cloud.ovh.net",
  "bucket": "ovh-stockage-videos",
  "access_key": "VOTRE_ACCESS_KEY",
  "secret_key": "VOTRE_SECRET_KEY",
  "region": "eu-west-par"
}

Cliquez Créer, puis Healthcheck → doit afficher OK.

Le JSON doit être valide : les clés entre guillemets doubles ", les valeurs texte entre guillemets, des virgules entre chaque paire (mais pas après la dernière).

11Créer les comptes

Si la base est vide (première installation), créez les comptes :

docker compose -f infra/docker-compose.deploy.yml exec backend python -m app.scripts.seed

Comptes créés : owner@vf.ai, admin@vf.ai, reviewer@vf.ai — mot de passe password123.

Sécurité : changez le mot de passe du compte owner dès la première connexion (bouton « Mot de passe » en bas de la barre latérale).

12Générer la première vidéo

  1. Séries & Pipelines → remplissez le formulaire (Titre, Type = Documentaire, Format = Photo-Cinéma, Durée 24, Épisodes 1, Sujet).
  2. Cliquez Créer (bouton en bas à droite).
  3. Dans le tableau, sur votre série : Dry run (vérifie coûts/risques), puis Lancer.
  4. Suivez la progression dans Jobs & Checkpoints, ou sur le serveur : docker compose -f infra/docker-compose.deploy.yml logs -f worker.

À la fin (statut done), la vidéo finale 1080p et le short sont dans votre bucket OVH, dans series/<id>/task_…/. Les fichiers intermédiaires sont supprimés automatiquement.

13Mettre à jour l'application

À lancer à chaque nouvelle version du code. À retenir absolument.

cd ~/VideoFactory git pull docker compose -f infra/docker-compose.deploy.yml --env-file infra/.env up -d --build docker compose -f infra/docker-compose.deploy.yml up -d --force-recreate nginx
Attendre la fin complète du build avant de tester. Pendant le build, le site peut afficher un 502 — c'est normal et temporaire.

14Dépannage (erreurs courantes)

« Unexpected token '<', "<html>…" is not valid JSON »

Le frontend reçoit du HTML au lieu du JSON → nginx renvoie une page d'erreur. Cause : le backend n'est pas joignable.

# Vérifier que le backend est healthy docker compose -f infra/docker-compose.deploy.yml ps # Si 502 persiste, recréer nginx (il a mémorisé une ancienne adresse) docker compose -f infra/docker-compose.deploy.yml restart nginx

« 502 Bad Gateway »

nginx ne joint pas le backend/frontend. Deux causes : (1) le build n'est pas fini, (2) nginx a gardé l'ancienne IP d'un conteneur recréé → restart nginx (corrigé définitivement par la config avec résolveur DNS).

Healthcheck stockage = KO avec « HeadBucket … 404 Not Found »

L'endpoint et les clés sont corrects, mais le nom du bucket est faux (majuscules, underscores, ou inexistant). Vérifiez le nom exact dans OVH.

Healthcheck = KO avec « AccessDenied » / « 403 »

La clé n'a pas la permission demandée. Ajoutez le rôle « operator/admin » à l'utilisateur S3, ou recréez un utilisateur S3 avec le bon rôle.

« relation "series" does not exist » (migration)

Corrigé (les clés étrangères cycliques ont été cassées). Si ça réapparaît sur une vieille base, repartez de zéro :

docker compose -f infra/docker-compose.deploy.yml down -v docker compose -f infra/docker-compose.deploy.yml --env-file infra/.env up -d --build docker compose -f infra/docker-compose.deploy.yml exec backend python -m app.scripts.seed

La page ne se charge pas depuis l'extérieur (mais marche en localhost)

Le pare-feu bloque le port 80. Ouvrez-le dans le groupe de sécurité de l'instance (étape 03).
